# 阶段 2 计划：桌面应用

目标：**把阶段 1 的命令行做成桌面应用**。选录像（或输入比赛 ID 下载）→ 选玩家 → 预览并勾选片段 → 一键录制、看进度 → 管理输出的视频；普通用户不用装别的东西，也不用碰命令行。

阶段 1 的命令行和全部规则保留不变，桌面应用和命令行共用同一套录制代码。阶段 1 的计划和实测见 [phase1-plan.md](phase1-plan.md)。

## 已定的决定

| 事项 | 决定 | 依据 |
|---|---|---|
| 技术栈 | Tauri 2 + Rust，前端原生 HTML/CSS/JS，没有前端构建步骤 | 和 dota2-game-helper2 一致，工程结构、发版脚本直接照搬 |
| ffmpeg | **随安装包附带** BtbN 编译的 LGPL、正式发布分支的 `ffmpeg.exe` | 普通用户不用自己装；LGPL 作为独立程序附带，义务比 GPL 少（附许可证和源码地址） |
| 录制时用户碰了鼠标键盘 | **检测到就停下并提示**，另配一个全局快捷键随时取消 | 误触会让点击落空、导出错段；命令行时代只靠倒计时提醒 |
| 界面语言 | 中文 + 英文，跟随系统、可切换 | 照 helper2 的 `i18n.js` + 语言文件 |
| 按比赛 ID 下载录像 | **放进阶段 2**：本地没有时从 OpenDota 拿下载地址 | 阶段 0 已验证下载，阶段 1 留作可选项 |
| 安装包和更新 | NSIS 安装包（装到当前用户）+ GitHub Releases 自动更新 | 和 helper2 一致 |

## 用户流程

```text
1. 录像列表：本地已下载的录像（比赛 ID、时间、时长、我玩的英雄和胜负）
   └─ 或输入比赛 ID：本地没有就从 OpenDota 下载
2. 比赛页：10 名玩家（默认选中自己）→ 选人
   └─ 片段列表：时间、被杀英雄、多杀/连杀标记、时长，可勾选；底部显示成片总时长和预计录制耗时
   └─ 高级：片段规则参数（和命令行的 --anchor、--max-lead 等对应），改了立刻重算
3. 开始录制前的确认：大字提示「录制期间不要动鼠标键盘，动了会自动停下」、取消快捷键、预计耗时；
   Dota 以普通模式开着时，说明要重启，用户确认后再继续
4. 录制中：当前片段 / 总数、当前步骤（启动游戏、加载录像、导出第几段、渲染进度）、已完成的文件
   游戏在前台，应用在后台；录完或停下后把应用切回前台
5. 结果：文件列表（时长、大小），打开文件、打开文件夹；可选合集
6. 设置：输出目录、录制分辨率、是否拼合集、录完是否退出游戏、语言、检查更新
```

## 关键做法

### 共用录制代码

把 `crates/d2hr/src/record.rs` 的流程搬进一个新的库 crate（暂名 `pipeline`），命令行和桌面应用都调用它。现在流程里直接 `println!` 和读标准输入的地方改成两个接口：

- **进度事件**：启动游戏、录像已加载、开始第几个片段、开始导出、渲染中（已用秒数 / 预计秒数）、片段完成（文件、时长）、合集完成、取消、出错。命令行把事件打印出来；桌面应用转成 Tauri 事件发给前端。
- **确认请求**：比如「要重启游戏，同意吗？」。命令行读标准输入，桌面应用弹对话框等用户点。

### 检测用户输入

- 录制期间装一个低级键盘、鼠标钩子（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`），放在单独的线程里跑消息循环。
- 钩子能区分真实输入和程序发出的输入：程序用 `SendInput` 发的事件带 `LLMHF_INJECTED` / `LLKHF_INJECTED` 标记，`PostMessage` 发的点击和按键根本不经过钩子。
- 只要来了一个真实输入，就当作按了一次 Ctrl+C：做完手上这一步就停，恢复设置，把应用切回前台，告诉用户「检测到鼠标键盘操作，已停止」，并给出「从没录完的片段继续」的按钮。
- `SetCursorPos` 会不会触发钩子、会不会被当成真实输入，要实测（见「待实测」）。
- 命令行也接上这套检测，默认开启，可以用参数关掉。

### 取消快捷键

录制期间注册一个全局快捷键（默认 `Ctrl+Shift+F12`，可在设置里改），效果同上。快捷键本身也是真实键盘输入，所以按快捷键和直接碰键盘效果一样。保留快捷键是为了给用户一个明确的「停下」操作。

### ffmpeg

- 安装包的 `resources` 里带 `ffmpeg.exe`，以及它的 LGPL 许可证和对应源码地址。
- 程序找 ffmpeg 的顺序：设置里指定的路径 → 安装目录自带的 → `D2HR_FFMPEG` → PATH。
- 版本固定，升级时和解析库一样走回归检查：裁剪、拼接、时长读取。

### OpenDota 下载

- 输入比赛 ID → 本地 replays 目录有就直接用 → 没有就查 OpenDota 的录像地址（没有地址时先请求解析，等一会儿再查）→ 下载、解压。
- 下载到哪里取决于实测：`playdemo` 能读 replays 目录以外的绝对路径，就下载到我们自己的目录，不碰游戏目录；不能的话，就下载到游戏的 replays 目录（和在游戏里点「下载」放的是同一个地方）。
- 只向 OpenDota 发比赛 ID，不发账号等其他信息。

### 窗口和前台

- 应用是普通窗口（不像 helper2 那样做悬浮层），单实例。
- 录制期间游戏在前台。每段导出完、录完或停下时，都按阶段 1 的做法把前台还回来；最终一定把应用切回前台，用户回来能直接看到结果或提示。

## 里程碑（各提一个 PR）

1. **共用录制代码 + 输入检测**：建 `pipeline`，命令行改为调用它，输出和现在一样；加上输入检测和取消快捷键，先在命令行里实测（含「待实测」第 1、2 项）。
   - 2026-10-26 实测：全程不碰时没有误判；中途动鼠标、按键都在 1 秒内停下，设置恢复，已做好的片段保留，并提示用 `--clips` 接着录。
   - 测试中发现：游戏已开着、刚重新加载录像时，第一次按追踪键偶尔不生效（连续两次复现）。改成最多按 3 次、每次等 5 秒，之后没再出现。
   - 测试中还出现过一次：中途停下后，剪辑工具的输出目录和时间轴长度没恢复。之后在追踪确认时、渲染途中各复现一次，都恢复正常，原因没查到。加了兜底：开始录制时，如果某项设置的当前值正好等于我们要设的值，就判定为残留，结束时恢复成游戏默认值（实测有效）；开始前清掉 tmp 里上一轮留下的视频。
   - 还发现一次录完后游戏仍在前台。改成录制开始时记下当时的前台窗口（终端或应用），整个流程结束后再兜底切回去，实测切回了 Claude。
2. **应用骨架**：Tauri 工程、录像列表、比赛页（选人、片段勾选、规则参数、预计耗时）、设置页、中英文。这一步还不录制，只用解析和计划。
   - 2026-10-26 完成，用户试过比赛页和设置。
   - 英雄名读游戏自带的本地化文件：`pak01_dir.vpk` 里的 `resource/localization/abilities_<语言>.txt`，键是 `npc_dota_hero_<名字>:n`。139 个英雄，新英雄也有，每种语言读一次约 12 毫秒（`game::vpk` 只读）。
   - 调试版一启动主线程就栈溢出，在 `build.rs` 里把主线程栈调到 8MB。调试版的解析器没有优化，解析一场录像要十几秒，正式版没有这个问题。
   - 设置存在 `%APPDATA%\dota2-highlight-recorder\settings.json`，片段规则参数改了也存进去。
3. **在应用里录制**：开始录制前的确认、进度、取消、结果页、录完切回前台、从没录完的片段继续。
4. **按比赛 ID 下载**：先测 `playdemo` 能不能读绝对路径，再接下载流程和进度。
5. **打包发布**：附带 ffmpeg 和许可证、NSIS 安装包、自动更新、发版脚本和 CI、README 改成以桌面应用为主的使用说明。

不新增单元测试，每个里程碑都靠实际运行来验证。
