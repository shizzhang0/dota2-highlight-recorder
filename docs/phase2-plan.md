# 阶段 2 计划：桌面应用

目标：**把阶段 1 的命令行做成桌面应用**。选录像（或输入比赛 ID 下载）→ 选玩家 → 预览并勾选片段 → 一键录制、看进度 → 管理输出的视频；普通用户不用装别的东西，也不用碰命令行。

阶段 1 的命令行和全部规则保留不变，桌面应用和命令行共用同一套录制代码。阶段 1 的计划和实测见 [phase1-plan.md](phase1-plan.md)。

## 已定的决定

| 事项 | 决定 | 依据 |

| ffmpeg | **随安装包附带** BtbN 编译的 ~~LGPL~~ **GPL**、正式发布分支的 `ffmpeg.exe`（2026-11-10 用户定） | 普通用户不用自己装；GPL 版带 x264，没有能用的显卡编码器也能录。作为独立程序附带，附上 GPL 许可证和对应源码地址 |
| 录制时用户碰了鼠标键盘 | ~~检测到就停下并提示，另配一个全局快捷键随时取消~~ → 里程碑 3 改成**暂停**，在游戏上方弹对话框问继续还是停止，快捷键去掉；录制方式改造后再改成 ~~Dota 在前台且有操作时才暂停~~ → **把发给 Dota 的点击和按键拦下，不暂停**（2026-11-10，见下方「检测用户输入」） | 误触会让点击落空、导出错段；命令行时代只靠倒计时提醒 |

| 录制方式 | ~~游戏自带的剪辑工具（点界面）~~ → **控制台 `startmovie` 逐帧输出 TGA，边录边用显卡编码，1080p，游戏放在最前面**（2026-11-06 定，11-07 实测通过；原定最小化，11-08 实测保持不住，改成放在后面；11-09 用户嫌切过去就被推回后面，改成放在最前面） | 不点界面、录制期间能用电脑、比剪辑工具快；见 [prototype-walkthrough.md](prototype-walkthrough.md)、[recording-review.md](recording-review.md) |

## 用户流程

最初的计划（里程碑 1–3 照此做的）：

```text
1. 录像列表：本地已下载的录像（比赛 ID、时间、时长、我玩的英雄和胜负）
   └─ 或输入比赛 ID：本地没有就从 OpenDota 下载
2. 比赛页：10 名玩家（默认选中自己）→ 选人
   └─ 片段列表：时间、被杀英雄、多杀/连杀标记、时长，可勾选；底部显示成片总时长和预计录制耗时
   └─ 高级：片段规则参数（和命令行的 --anchor、--max-lead 等对应），改了立刻重算
3. 开始录制前的确认：大字提示「录制期间不要动鼠标键盘，动了会自动停下」、取消快捷键、预计耗时；
   Dota 以普通模式开着时，说明要重启，用户确认后再继续
4. 录制中：当前片段 / 总数、当前步骤（启动游戏、加载录像、导出第几段、渲染进度）、已完成的文件
   游戏在前台，应用在后台；录完或停下后把应用切回前台
5. 结果：文件列表（时长、大小），打开文件、打开文件夹；可选合集
6. 设置：输出目录、录制分辨率、是否拼合集、录完是否退出游戏、语言、检查更新
```

现在的交互以 [app-interaction.md](app-interaction.md)（导航、首页、已录视频）和 [prototype-walkthrough.md](prototype-walkthrough.md)（录制流程）为准。主要变化：
固定导航「比赛 · 已录视频 · 设置」；首页只列本地录像，可按比赛 ID 下载、批量删除；结果页并进"已录视频"；
录制方式改造后，游戏放在最前面录，进度显示在主窗口，录完或出错弹系统通知。

## 关键做法

### 共用录制代码

把 `crates/d2hr/src/record.rs` 的流程搬进一个新的库 crate（暂名 `pipeline`），命令行和桌面应用都调用它。现在流程里直接 `println!` 和读标准输入的地方改成两个接口：

- **进度事件**：启动游戏、录像已加载、开始第几个片段、开始导出、渲染中（已用秒数 / 预计秒数）、片段完成（文件、时长）、合集完成、取消、出错。命令行把事件打印出来；桌面应用转成 Tauri 事件发给前端。
- **确认请求**：比如「要重启游戏，同意吗？」。命令行读标准输入，桌面应用弹对话框等用户点。

### 检测用户输入

- 录制期间装一个低级键盘、鼠标钩子（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`），放在单独的线程里跑消息循环。
- 钩子能区分真实输入和程序发出的输入：程序用 `SendInput` 发的事件带 `LLMHF_INJECTED` / `LLKHF_INJECTED` 标记，`PostMessage` 发的点击和按键根本不经过钩子。
- 只要来了一个真实输入，就当作按了一次 Ctrl+C：做完手上这一步就停，恢复设置，把应用切回前台，告诉用户「检测到鼠标键盘操作，已停止」，并给出「从没录完的片段继续」的按钮。
- `SetCursorPos` 会不会触发钩子、会不会被当成真实输入，要实测（见「待实测」）。
- 命令行也接上这套检测，默认开启，可以用参数关掉。

后来的变化：
- 里程碑 3：桌面应用里改成**暂停**（命令行仍是停止）。游戏上方弹置顶对话框问继续还是停止，主窗口上也能点；继续时重新加载录像、设好镜头，重录被打断的那一段。
- 录制方式改造（D10）：程序不再点界面，用户动鼠标键盘不干扰录制，只有操作进了 Dota 才会。
  改成 **Dota 在前台、并且检测到用户操作时才暂停**；只看前台不行，因为 Dota 会自己变成前台窗口（2026-11-07 实测）。
  原想录制期间把 Dota 最小化，但回放一播放它就自己恢复、抢前台（2026-11-08 实测），改成放在其他窗口后面、抢前台时还回去；
  用户切过去看一眼也被推回后面，体验差，2026-11-09 改成 Dota 一直在最前面。
  暂停只算点击、滚轮、按下按键（Alt、Win 键不算），程序刚让回放播放的 1.5 秒内不算。继续时不重新加载录像，跳回断点、重新设镜头就接着录（D12）。
- 2026-11-10（D10）：**不再暂停，改成拦截**。同一个钩子把发给 Dota 的输入吞掉：Dota 在前台时的按键、光标在 Dota 上时的点击和滚轮；
  修饰键和切窗口的组合键、鼠标移动、程序自己发的输入放行。只留停止：Dota 左上角进度窗和主窗口上的「停止录制」按钮、命令行的 Ctrl+C。
  命令行的 `--allow-input` 改成不拦截。

### 取消快捷键

~~录制期间注册一个全局快捷键（默认 `Ctrl+Shift+F12`，可在设置里改），效果同上。~~ 里程碑 3 去掉了：键盘钩子在按下修饰键那一刻就检测到输入，快捷键只是"动键盘"的一种（里程碑 1 实测）。

### ffmpeg

- 安装包的 `resources` 里带 `ffmpeg.exe`，以及它的 GPL 许可证和对应源码地址。
  **定（2026-11-10）**：BtbN 的 **n9.0.2 GPL shared** 构建，取自它的月底存档 `autobuild-2026-10-31-12-59`
  （每天的构建只留两周左右，月底的长期保留），文件 `ffmpeg-n9.0.2-39-g7adfbe40dc-win64-gpl-shared-9.0.zip`，
  SHA256 写死在 `tools/release.py` 里，下载后核对。只带 `ffmpeg.exe` 和它要的 DLL（不带 ffplay、ffprobe），
  装到安装目录的 `ffmpeg\` 下，另附 `LICENSE.txt`（GPLv3）和一份说明（版本、源码提交、构建脚本地址）。
- 程序找 ffmpeg 的顺序：设置里指定的路径 → 安装目录自带的 → `D2HR_FFMPEG` → PATH。
- 版本固定，升级时和解析库一样走回归检查：裁剪、拼接、时长读取。
- 录制方式改造后，ffmpeg 还要**边录边编码**（显卡编码器优先，见 `media::encode`）。
  BtbN 的 LGPL 版不带 x264（x264 是 GPL），没有显卡编码器的机器就没有退路；GPL 版作为独立程序附带、附上许可证和源码也可以（luckcaty-cut-dota2 就是这么做的）。**定：用 GPL 版**（2026-11-10 用户定），保证每台电脑都能录。

### OpenDota 下载

- 输入比赛 ID → 本地 replays 目录有就直接用 → 没有就查 OpenDota 的录像地址（没有地址时先请求解析，等一会儿再查）→ 下载、解压。
- ~~下载到哪里取决于实测：`playdemo` 能读 replays 目录以外的绝对路径，就下载到我们自己的目录，不碰游戏目录。~~
  **定：下载到游戏的 replays 目录**（和在游戏里点「下载」放的是同一个地方），游戏里也能看到；应用里删除录像时，游戏里也跟着消失（用户需要：国服客户端进某些录像会闪退）。
- 只用 OpenDota 的"按比赛查"拿录像地址。"按玩家列比赛"会落后几个月（2026-10-27 实测），不用。
- 只向 OpenDota 发比赛 ID，不发账号等其他信息。
- 下载进度（里程碑 4，2026-11-10 定）：首页输入框下面分阶段显示——向 OpenDota 要地址（要它去取时显示已等几秒、最多 2 分钟）、
  下载（进度条 + 已下 / 总共 MB + 速度；服务器不报大小时只显示已下多少）、保存。旁边有「取消」，取消后删掉没下完的文件。
  边下边解压写盘，不再把整个压缩包读进内存。下载时切到别的页面，下载照常在后台进行，回到首页接着显示进度；
  切走期间下完了，回来显示"下好了"和「打开」，不在用户看别的页面时自动跳到比赛页（原来会）；失败了回来显示原因。
  连 OpenDota 或下载服务器遇到网络问题（连接被断、TLS 握手失败、超时）自动重试 2 次，明确的 404 之类不重试。

### 窗口和前台

- 应用是普通窗口（不像 helper2 那样做悬浮层），单实例。
- ~~录制期间游戏在前台。每段导出完、录完或停下时，都按阶段 1 的做法把前台还回来；最终一定把应用切回前台。~~
  录制方式改造后，~~游戏放在其他窗口后面，抢前台时还回去~~ → **游戏放在最前面**（2026-11-09）；录完或停下时把应用切回前台。
  录完或出错弹系统通知（Windows 上点通知不会打开应用）。

## 里程碑（各提一个 PR）

1. **共用录制代码 + 输入检测**：建 `pipeline`，命令行改为调用它，输出和现在一样；加上输入检测和取消快捷键，先在命令行里实测（含「待实测」第 1、2 项）。
   - 2026-10-26 实测：全程不碰时没有误判；中途动鼠标、按键都在 1 秒内停下，设置恢复，已做好的片段保留，并提示用 `--clips` 接着录。
   - 测试中发现：游戏已开着、刚重新加载录像时，第一次按追踪键偶尔不生效（连续两次复现）。改成最多按 3 次、每次等 5 秒，之后没再出现。
   - 测试中还出现过一次：中途停下后，剪辑工具的输出目录和时间轴长度没恢复。之后在追踪确认时、渲染途中各复现一次，都恢复正常，原因没查到。加了兜底：开始录制时，如果某项设置的当前值正好等于我们要设的值，就判定为残留，结束时恢复成游戏默认值（实测有效）；开始前清掉 tmp 里上一轮留下的视频。
   - 还发现一次录完后游戏仍在前台。改成录制开始时记下当时的前台窗口（终端或应用），整个流程结束后再兜底切回去，实测切回了 Claude。
2. **应用骨架**：Tauri 工程、录像列表、比赛页（选人、片段勾选、规则参数、预计耗时）、设置页、中英文。这一步还不录制，只用解析和计划。

   - 设置存在 `%APPDATA%\dota2-highlight-recorder\settings.json`，片段规则参数改了也存进去。
