# 技术验证 6：游戏自带的视频剪辑工具

**决定（2026-10-21）：录制用游戏自带的视频剪辑工具，OBS 作为备选**（剪辑工具出问题时，或者用户想用自己的 OBS 设置时）。

结论：**可行，而且很可能比 OBS 更好**。Dota 2 回放里自带"视频剪辑工具"（Clip Builder），能直接把一段回放渲染成 mp4：有声音、原生分辨率、60 帧，镜头就是当前的观战镜头（英雄追踪）。
如果后续能把"选择起止时间"也自动化，录制可以完全不依赖 OBS。

## 设置项（2026-10-21，`cvarlist`）

没有 Source 1 那种 `startmovie`，也没有触发剪辑的控制台命令（`help dota_clip_builder` 显示不存在），但有一组设置项，都带 `archive` 标记（会写进用户配置）：

| 设置项 | 默认值 | 说明 |
|---|---|---|
| `dota_clip_builder_format` | `mp4` | 输出格式 |
| `dota_clip_builder_framerate` | 60 | 帧率，导出对话框里的滑块 |
| `dota_clip_builder_bitrate` | 30 | 码率（Mbps），导出对话框里的滑块 |
| `dota_clip_builder_high_quality_rendering` | true | 高质量渲染（勾选项） |
| `dota_clip_builder_hide_game_ui` | false | 隐藏游戏界面（勾选项） |
| `dota_clip_builder_max_duration` | 60 | 单个片段最长时长（秒） |
| `dota_clip_builder_output_folder` | 空 | 输出文件夹；为空时是 `文档\dota_clips` |
| `dota_clip_builder_seconds_graduation` | 1 | 时间轴刻度？ |

其他名字里带 record 的项目都不是录比赛画面用的：`dota_record_webm` 录英雄的透明 webm 动画，`dota_recorder_*` 录英雄肖像动画，`record` / `tv_record` 录 `.dem` 录像文件。

## 操作流程（实测）

```text
加载录像，跳到目标时间附近，设好英雄追踪 + 本方迷雾（菜单）
点回放面板左下角的剪刀按钮 (2198,520)   提示："视频剪辑工具 - 检查并导出游戏视频"
  → 屏幕下方出现"视频剪辑工具"面板：
      时间轴 = 当前时间 ±30 秒（这次是 03:30 — 04:30），上面有一对选区把手
      播放控制、文件夹图标、"导出视频"按钮 (1840,1528)
点"导出视频" → 弹出"视频导出设置"：
      高质量渲染、隐藏游戏界面、帧率 60、比特率 30 Mbps、预计文件大小
点对话框里的"导出视频" (1124,1036) → 游戏从选区起点开始播放并渲染
```

坐标是 2560×1600、150% 缩放下的物理像素。点击方法和技术验证 5 一样：`SetCursorPos` 加 `SendInput` 微移动，再用 `PostMessage` 点击。

## 和 OBS 方案比

| | 视频剪辑工具 | OBS |
|---|---|---|
| 要装的东西 | 不用 | OBS（或我们代下的便携版） |
| 画质 | 引擎渲染，不受实时性能影响，不掉帧 | 屏幕捕获，受实时性能影响 |
| 声音 | 自带 | 游戏捕获源 + 关掉后台静音 |
| 速度 | 比实时慢约 1.8 倍 | 实时 |
| 控制方式 | 只能点界面（剪刀、导出、选区把手） | WebSocket，完全程序化 |
| 剪掉空档 | 每个连续区间导出一个文件，再用 ffmpeg 拼起来 | 录制时暂停 |

## 精确选择起止时间（2026-10-21 第二次测试）

**结论：可以精确到秒**，做法是拖动选区把手，再悬停读出把手旁边显示的时间来核对。

### 时间轴的规律

- **时间轴 = 以当前播放位置为中心、长度为 `dota_clip_builder_max_duration` 的窗口**：
  - 默认 60 秒：在 4:00 打开，时间轴是 03:30 — 04:30；
  - 改成 120 秒后：时间轴变成 02:33 — 04:33（当时的播放位置是 3:33）。
- 时间轴横条在客户区 x ≈ 715 — 1807（1092 像素），y = 1452：
  - 60 秒窗口是 18.2 像素/秒，120 秒窗口是 9.1 像素/秒；
  - 换算公式：`x = 715 + (t − 窗口起点) × 1092 / 窗口秒数`。
- **默认选区是固定的像素位置**（把手在 x = 1117 和 1438），不是按时间算的，所以每次都要拖。
- **时间轴上方会标出窗口内的每次击杀**（击杀者头像在上、被杀者头像在下），可以用来核对。

### 拖动

- 拖动 = 在把手上按下鼠标，分 12 步移到目标位置（每步都带 `MK_LBUTTON` 的 `WM_MOUSEMOVE`，同时真实移动光标），再抬起。用的还是 `PostMessage` 加光标移动那一套。
- 悬停在把手上会显示时间：
  - 第一次拖到 1279 / 1643，显示 04:01 / 04:21，各差 1 秒；
  - 各往左挪 18 像素后，显示 **04:00 / 04:20**，正好。
- 导出这段（60 秒窗口），**GSI 显示游戏从 4:00 播到 4:20**，视频 20.42 秒，2560×1600，双声道。

### 超过 60 秒的片段

- 把 `max_duration` 改成 120，拖出 3:00 — 4:30 的选区（90 秒）导出：**提示"导出视频成功"，但文件是 0 字节**，游戏也没有开始播放。
- 同样在 120 秒窗口下，用默认选区（约 36 秒）导出：正常，GSI 显示从 2:28 播到 3:04，视频 36.02 秒。
- **所以单个导出不能超过约 60 秒**，更长的片段要分段导出，再用 ffmpeg 拼起来。`max_duration` 可以调大窗口，方便一次看到更大范围。

### 渲染完成的信号

- 完成后屏幕中间会弹出"**导出视频成功** 保存 clipN.mp4 至 …\dota_clips"，要点"确定"（1280, 880）关掉，否则会挡住后面的操作。
- 文件名按 clip1、clip2… 递增。程序可以等新文件出现，并且大小连续几秒不变，再结合这个提示框来判断完成。注意：失败时同样会弹"成功"，但文件是 0 字节，所以**一定要检查文件大小**。

### 其他

- 渲染速度：20 秒的片段约 34 秒渲染完，36 秒的片段约 65 秒，大约是实时的 1.7–1.8 倍。
- 导出前后，播放位置会变（导出会从选区起点播放到终点），下一段要重新跳转。

## 还没解决

1. ~~渲染期间游戏要不要一直在前台~~ 2026-10-22 已测：不用，后台渲染也有声音（见下方"里程碑 2 实测"）。
2. "隐藏游戏界面"的效果，以及**导出视频里底部中间 HUD 空白**的原因：2026-10-22 用户确认导出的视频都看不到装备栏。视频里底部 HUD 的边框、头像、右下角还在，技能栏、装备栏、血条蓝条都是空的；导出时游戏画面上这些是有的（剪辑工具面板下方能看到血量），所以是渲染视频时没画进去。网上没找到相关说明。
   视频里底部的头像看着也不是被追踪的幻影刺客，像是渲染时 HUD 没拿到"当前选中的单位"。
   下次测试的对比实验（同一段约 10 秒的范围各导出一次，取一帧看底部 HUD；用 `export_one` 的 `--set` 临时改设置、`--tag` 区分文件名）：
   - 先只读地查设置项：`find clip_builder`、`find hud`、`find spectator`，看有没有控制导出时界面的项目；
   - 基准：现在的流程（菜单设英雄追踪 + 数字键选人）；
   - 不按数字键、改用鼠标点上方英雄头像选人（`--no-focus`，手动点击的部分由程序做）；
   - 换镜头模式：不设英雄追踪，保持默认镜头（`--no-setup`）；
   - `dota_clip_builder_high_quality_rendering 0`；
   - `dota_clip_builder_hide_game_ui 1`，看隐藏的是哪些界面、和缺的那块是不是同一层；
   - 换一个天辉方玩家，排除阵营的影响。
   都不行就考虑：装备栏只在 OBS 方案里有，让用户在两种录制方式之间选。

   **2026-10-22 实验结果：找到原因**（同一段 31:57–32:07，各导出一次，取一帧看底部 HUD）：

   | 实验 | 底部中间（技能、装备、血条蓝条） |
   |---|---|
   | 基准（菜单英雄追踪 + 数字键） | 空 |
   | 点顶部头像选人 | 空（GSI 显示追踪对了） |
   | `dota_clip_builder_high_quality_rendering 0` | 空 |
   | `dota_clip_builder_hide_game_ui 1` | 整个 HUD 都没了（设置项生效） |
   | 不设镜头、不选人 | 空 |
   | 天辉方玩家（灰烬之灵） | 空，但头像正确换成了灰烬之灵 |
   | **点完导出后再按几次数字键**（`--refocus`） | **完整**：技能、装备、血量蓝量、属性都在 |

   推断：导出时剪辑工具自己跳回选区起点（日志里有 `received full update`），选中单位被清掉了；
   头像跟的是镜头追踪对象，所以一直是对的；中间这块显示的是选中单位，就空了。
   我们自己跳转后都会再按数字键，所以导出前画面上是有的。
   做法（已改成每次导出都做）：点完导出立刻开始按追踪键，每 0.5 秒一次、连按 4 秒。
   用 ffmpeg 每 0.25 秒取一帧核对：两段视频**从第一帧起**底部 HUD 就是完整的。
   连第一次实验（点完导出 1.5 秒后才按第一下）也是，因为剪辑工具要先跳回起点才开始出画面。
   只读查到的设置项里，剪辑工具只有已知的 8 项，没有控制导出界面的；HUD 相关的只有 `dota_hud_force_query`（作弊）、
   `dota_hud_new_query_panel` 和查询面板有关，没用上。

## 里程碑 2 实测（2026-10-22）

用 `crates/recorder/examples/export_one.rs` 全自动导出（比赛 9052676196，7 号玩家幻影刺客，2560×1600 窗口化）：

| 导出 | 计划 | 视频时长 | 渲染耗时 | 渲染期间 GSI 时钟 | 备注 |
|---|---|---|---|---|---|
| 片段 7（三杀） | 31:56–32:14，18.3 秒 | 18.69 秒 | 39.5 秒 | 31:55 → 32:14 | 悬停显示 31:56 / 32:14，正好 |
| 手动范围 | 31:10–32:08，58 秒 | 59.19 秒 | 109.7 秒 | 31:08 → 32:08 | 120 秒窗口下 58 秒可以导出 |
| 片段 5（双杀） | 27:22–27:35，12.9 秒 | 13.28 秒 | 28.5 秒 | 27:20 → 27:34 | 点完导出就切回前台，后台照样渲染完 |
| 片段 6 | 31:26–31:39，13.7 秒 | 13.92 秒 | 30.0 秒 | 31:24 → 31:39 | 同上，另把 `snd_mute_losefocus` 设成 0 |

视频比计划长 0.2–1.2 秒，在 2 秒的容差内。后台渲染的两段用户试听都有声音：剪辑工具是引擎内部渲染，不受 `snd_mute_losefocus` 影响，不用改这个设置（OBS 方案才需要）。音轨是固定码率（约 160 kbps），从帧大小看不出是否静音，只能人耳听。

踩到的问题（代码都已改好）：

- **暂停状态下跳转**：控制台照样输出 `Demo Skipping finished at tick N`，但画面和剪辑工具的时间轴都不更新（时间轴显示的还是开局前 -1:56 — 0:03），导出的范围就全错了。要先 `demo_resume`，跳完再 `demo_pause`，并用 GSI 时钟确认到位。
- **暂停在某个 tick 时再跳到同一个 tick**：等满 60 秒也没有完成标志（推断是什么都不做）。
- **播放头不一定在时间轴正中**：这次偏右 22 像素（约 2.4 秒）。改成打开剪辑工具后截图，在 y = 1415 这一行找播放头滑块（只有它是亮的，约 15 像素宽），以它为基准换算把手位置。
- **暂停时 GSI 几秒才推一个包**（`heartbeat 1.0` 不管用，游戏在后台时更少）：先清旧包、再操作、再等，否则会把反映操作结果的那个包也清掉。
- **启动的游戏继承了我们的标准输出管道**：调用方要等游戏退出才算命令结束。启动前把自己的标准句柄设成不可继承。
- **游戏崩溃一次**（access violation，`dota2_2026_1022_212310_0_accessviolation.mdmp`）：点导出后剪辑工具往回跳到选区起点时崩的；之后从头重开，4 次导出都没再出现。崩溃时改过的设置没有写进配置文件（游戏正常退出时才写），GSI 配置文件留了下来，已手动删除；设置守护已改成某项恢复失败也继续做完，并且一定删 GSI 配置。
- 运行时改 `dota_clip_builder_output_folder` 立即生效；文件名接着目录里已有的 clipN 编号。
