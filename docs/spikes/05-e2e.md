# 技术验证 5：端到端

结论：**可行**。给定比赛、玩家、时间段，可以全自动录出一段**英雄追踪视角、该玩家阵营迷雾**、有声音、时间准确、文件名清楚的视频。
镜头模式和迷雾要在**每次加载录像之后**通过观战菜单设置（短暂切到前台，用真实鼠标移动加窗口消息点击，约 3 秒），详见下面"锁定镜头的最终做法"。

### 锁定镜头的最终做法（2026-10-20 实测成功）

```text
playdemo → 等 GSI 报出时钟 → demo_gototick 起点 → demo_pause
切到前台 → 点菜单：展开面板 ▸ (2465,106) → 镜头下拉 (2380,182) → 英雄追踪 (2300,370)
                     → 迷雾下拉 (2380,242) → 迷雾：天辉 (2310,337) / 夜魇（下一项）
后台按数字键（玩家序号 + 1）→ 英雄追踪切到该玩家
开录 → demo_resume → 计时 → 停录
```

- **每次点击的做法**：先 `SetCursorPos` 把系统光标放到目标点，再用 `SendInput` 发一个 ±1 像素的相对移动，让游戏收到移动事件、把游戏内光标移过去（这时会出现悬停提示）；**点击本身用 `PostMessage` 发 `WM_LBUTTONDOWN/UP`**。`SendInput` 的点击游戏不响应。
- **重新加载录像（`playdemo`）会把镜头模式重置成"自由视角"**，面板也会收起。所以菜单设置要放在加载之后；`record_clip` 加了 `--no-reload`，录像已经加载好时就不再重新加载。
- `spec_autodirector` 不影响 Dota 的镜头模式，`record_clip` 已经不再发这条命令。
- 后台按 F2 时，菜单里的迷雾选项没有变化，所以迷雾也改用菜单设置。
- 坐标是在 2560×1600、150% 缩放下量的（物理像素）。正式版要按窗口大小换算，点完截图核对模式名称。
- 在开发环境里，这条点击命令要在沙箱外执行（见下面"第二次尝试"）。正式程序不受影响。

成品：`9046032624_2_juggernaut_04-00_04-20.mp4`，20.03 秒，双声道。录制中途截图（4:10）显示"英雄追踪 · 主宰""迷雾：天辉"，镜头正对 GGBOND 所在的团战。

## 怎么跑

```bash

    --match 9046032624 --player 2 --from 4:00 --to 4:20 --extra "-perfectworld"
```

## 过程中发现、已经修掉的问题

| 问题 | 原因 | 处理 |
|---|---|---|
| `tick_at` 一开始一个采样点都没有 | 新录像没有 `m_fGameTime` | 改用"网络 tick − 累计暂停 tick"推算（同 opendota 的做法）。11 场录像里，击杀时间换算回 tick 的误差都不超过 2 tick |
| 游戏刚启动时读控制台变量失败 | netcon 端口开得早，命令要等加载到一定程度才有回应 | 先反复发 `echo`，等到回应再继续（`Netcon::wait_responsive`） |
| 自动启动游戏后程序不退出 | 游戏继承了程序的输出管道 | 启动时把游戏的标准输入输出都设为 null |
| 第一次只录了 10.6 秒 | 开录前那次暂停留下的 GSI 包积压在通道里，等"暂停"时读到了旧消息 | 改为计时停止；读 GSI 前先清空积压的包 |
| `demo_pauseatservertick` 没在终点停下 | 实测无效：按服务器 tick、按录像 tick 理解都不对，一直播放过了 5:08 | 不再使用，改为按 1 倍速计时 |
| 游戏崩溃：`FATAL ERROR: CopyNewEntity: invalid class index (3227), out of range 0` | 手动测试时，加载完成标志出现后只等了 3 秒就发 `demo_gototick`，客户端还没收到实体类表 | 跳转前一定要等到 GSI 报出这场比赛的时钟（`record_clip` 已经这样做）。崩溃前改的设置没有写进配置文件 |
| 跳转命令被吞掉 | 游戏里本来就在放同一场录像，GSI 立刻报出比赛 ID（旧状态），程序在重新加载期间就发了跳转命令 | 以控制台的加载完成标志为准 |

## 锁定镜头的排查过程

- 这次的录像里，右上角显示的是"**自由视角**"。按键选中了 Juggernaut，但镜头没有一直跟着他。
- 在"自由视角"下，单击、双击数字键都切不回"英雄追踪"。
- 用 `PostMessage` 点右上角的菜单，这次**完全没点到界面上**，反而让地图镜头挪动了。技术验证 2 里在同样的位置点开过菜单，说明这种做法不可靠。
- 自由视角可能有两个来源：这类点击被当成了地图上的操作；或者鼠标靠在窗口边缘时，触发了"边缘拖动临时接管镜头"（`dota_spectator_enable_edgepan_temporary_free_camera`，默认开）。
- 镜头模式在 GSI 里没有对应字段，也没有对应的配置项，只能靠截图判断。

可选的办法（待定）：

1. **开录前短暂切到游戏前台，用真实输入点菜单**（参考项目的 SendInput 思路）。只在设置镜头模式的那一两秒抢焦点，点完截图确认模式名称；同时把 `dota_spectator_enable_edgepan_temporary_free_camera` 设为 0，录完恢复，防止被鼠标意外接管。点击坐标要按窗口大小换算。
2. **自己控制镜头**：本来就处在自由视角，用 `spec_goto` 按解析出的英雄坐标逐帧移动镜头。完全不碰界面，结果可预期，但要自己处理镜头平滑，`spec_goto` 在 Dota 里是否有效也还没测。
3. **半自动**：开录前提示用户在游戏里手动选一次镜头模式，之后同一场内切换玩家都用数字键。

### 办法 1 的第一次尝试（2026-10-19，没完成）

- 把 Dota 切到前台：先模拟按一下 Alt 键，再调 `SetForegroundWindow`，可以成功。
- **`SendInput` 的结构体大小必须正好是 40 字节**（64 位）。一开始多了填充字段，变成 48 字节，系统直接拒绝调用（返回 0），点击全部无效。修正后返回 1。
- 真实点击确实落在了预期位置：点 (2423, 388) 时，"下个精彩时刻"按钮出现了悬停高亮。
- 但点镜头模式下拉框 (2380–2420, 182) 后，**一直没看到下拉列表**，不管用 `PrintWindow` 截窗口还是截屏幕都一样。原因还没查清。
- 测试期间前台被别的窗口（Claude）抢走了一次。**这个办法要求设置镜头的那几秒没人碰电脑**，在用户正在用电脑时很难稳定。
- 面板展开后布局会变：倍速"+"按钮从 y≈388 下移到 y≈520，原来 y≈388 的位置变成了"下个精彩时刻"按钮（点到它会让回放跳走）。按坐标点击必须先确认面板当前的状态。
- `dota_spectator_enable_edgepan_temporary_free_camera` 原值 `true`，测试时设为 0，结束后已恢复。

### 办法 1 的第二次尝试（2026-10-20，用户离开电脑）

- **在开发用的命令环境里，`SendInput` 的鼠标移动和点击都不起作用**：函数返回 1、`GetLastError` 为 0，但光标一动不动。Claude 在前台时也一样，所以不是 Dota 在拦截，而是命令运行的沙箱拦掉了模拟输入（进程是 Medium 完整性级别，`SetCursorPos` 和 `PostMessage` 都正常）。前一天"点了没反应"也是这个原因。
- 系统缩放是 150%：坐标换算前要先调 `SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，否则 `ClientToScreen` 和截屏用的是缩放后的逻辑坐标，会差 1.5 倍。加上之后，光标能准确移到客户区 (2465, 106)。
- 点标题"自动视角"本身不会展开面板。展开按钮应该是标题右边的小三角（展开后变成"▾"），但因为上面的原因没能验证。
- 我们自己的程序正式运行时不在这个沙箱里，`SendInput` 应该能正常工作。要在开发环境里验证，需要让这条命令在沙箱外执行，**待用户同意**。

### 只用后台按键的尝试（2026-10-19）

目标：英雄追踪 + 该玩家所在阵营的战争迷雾，全程不抢前台、不点菜单。

| 要确认的 | 结果 |
|---|---|
| 战争迷雾 | **可行**。热键 `SpectatorFOWBoth` / `SpectatorFOWRadient` / `SpectatorFOWDire` 默认是 F1 / F2 / F3，用 `PostMessage` 发 F2 后，小地图上的夜魇英雄消失、野怪营地出现，即只显示天辉的视野 |
| 镜头模式会不会被重置 | **同一次游戏运行里会一直保留**，重新加载录像也不变；只有重启游戏后才回到"自动视角" |
| 关掉边缘接管 | 能防止进入自由视角，但已经在自由视角时关掉，也切不回来 |
| 从"自动视角"按数字键 | **只选中玩家**（GSI 的 `selected_unit` 跟着变），**模式没变成英雄追踪**。暂停时、播放时、先关自动导播、先发 `spec_mode 4`、发给主窗口或输入法窗口，都一样 |

技术验证 2 那次按 3 确实切到了"英雄追踪"，但这次没能复现，原因还不清楚。

### 有没有切换镜头模式的控制台命令（2026-10-19）

netcon 连的就是游戏里按 `~` 打开的那个控制台，两边的命令完全一样。

- 网上查到的候选：`dota_spectator_mode`、`spec_track`、`cl_spec_mode`、`dota_toggle_free_camera`。
  用 `cvarlist` 导出当前版本的完整列表（2622 条），**这几个都不在里面**，应该是新版本里删掉或改名了。
- 列表里和观战镜头有关的只有 `spec_mode`、`spec_player`、`spec_next/prev`、`spec_goto`、`spec_autodirector`、`spec_centerchasecam`。
- 在播放状态下实测，镜头模式一直是"自动视角"：
  - `spec_player GGBOND`（按名字）、`spec_next`、`spec_player 3`；
  - `dota_camera_hold_select_to_follow 1` 后按 3 / 按住 3 1.5 秒（测完已改回 `false`）。
- **结论：当前版本没有能切换观战镜头模式的控制台命令。** 剩下的路只有界面操作（办法 1）或者自己控制镜头（办法 2，`spec_goto` 在列表里，带 `clientcmd_can_execute` 标记，还没实测）。

结论：战争迷雾用 F1–F3 解决；**镜头模式仍然没有不依赖界面的稳定做法**。剩下的候选：

- 办法 1（真实输入点菜单），前提是用户在那几秒不碰电脑，而且还要先查清下拉列表为什么没打开；
- 办法 2（`spec_goto` 自己控制镜头）。我们经常本来就处在自由视角，正好适合这个办法，但 `spec_goto` 在 Dota 里是否有效还没测。
